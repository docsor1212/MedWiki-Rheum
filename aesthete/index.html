01
THE PROBLEM

模型配色的失手,是结构性的

大模型输出的配色经常不可用,原因有三个,而且都与模型规模无关:

一,hex 被当作文本处理。模型在 token 空间里"背诵"颜色,而不是在感知空间里比较它们——两个 hex 放在一起是否协调,它没有把握。

二,输出回归训练中位数。公开前端教程里出现频率最高的配色倾向是紫与蓝。没有外部约束时,模型会稳定地漂回这个中位数,产出千篇一律的"AI 味"。

三,模型看不见自己的输出。它无法渲染一张图再检查文字是否可读、色盲用户是否分辨得出。而这三件事,恰恰是配色工程里必须验证的部分。

aesthete-agent 的做法不是换一个更聪明的模型,而是把品味外包给流程——检索先于生成,派生先于偏好,验证先于交付。
02
METHOD

六步流程,每步有机制

从一句话需求到一份通过验收的配色,引擎按固定顺序执行六步。其中任何一步失败,流程会停下来并给出修复建议,而不是继续输出。

Brief需求解析为语域与约束,用户指定的颜色是绑定条件
→
Match117 块实证色板按语域排序,人气分层+客观质量双过滤
→
DeriveOKLCH 派生角色:纸底/墨字/口声,60-30-10 配比
→
Render十个真实场景画布,设备框与内容密度同真实交付一致
→
Gates四道机械闸,任一失败即中止并给出修复建议
→
Verdict裁决回写:色板库与偏好档案随每次验收进化

角色派生在 OKLCH 空间完成:大底抬亮与降饱和有固定公式,文字与底色的对比度在派生时就已确定,而不是渲染后碰运气。

03
MECHANICAL GATES

四道闸门,退出码即裁决

每一份输出都要过四道闸。闸门只认数字,不认修辞——下面这组卡片里的每个数字,都来自引擎对本文档所用色板的实测。

GATE 1 · CONTRAST对比度

WCAG 2.2 边界值逐对检验(#767676 通过、#777777 不通过,这种级别的边界都在测试集里),可选 APCA 感知算法。本文档正文对底色实测 5.57:1,AA 通过。失败时输出修复建议:沿 OKLCH 抬升亮度直到达标。

GATE 2 · COLOR-BLIND色盲安全

红色弱/绿色弱/蓝色弱三种模拟逐一检查色间分离度,分类色板要求去盲分离度 ≥ 0.08。模拟是诚实的:分离度下降会如实标出,并给出"改靠明度差或加标签"的替代方案。

GATE 3 · AI-SLOP签名检测

检测四类高发签名:训练中位数色族、紫渐变倾向、平坦明度、全高饱和。命中即非零退出。另有一条工程铁律:任何渐变一律不合格,纯色分层替代。

GATE 4 · SCORECARD五维评分

明度弧、饱和分布、角色配比、语义一致性、可访问性,五维合计 20 分,低于 10 分非零退出。对本色板实测 15/20,并如实附上一条 P1:红绿色盲下两色碰撞,建议靠明度差或加标签。

四闸聚合为一条 report 命令:一次调用输出单份 PASS/FAIL JSON,退出码即裁决,可直接接入 CI。

04
SCENES

十个场景,所见即交付

色板不适合用色卡评审。引擎把配色渲染进十个真实场景——移动应用、落地页、仪表盘、品牌、字阶、图表、商品卡、邮件、编辑页、图案——大画布、设备框、真实内容密度。浅色与暗色两套主题均由角色派生公式驱动,暗色大底自动抬亮降饱和,避免"黑压压"。

交互版:打开完整 Showcase(二十块收藏色板 × 全部场景,与你正在看的这份文档同款色板)。场景画布同样过闸:渐变零容忍,文字对底色逐点检查。

05
EVIDENCE LIBRARY

117 块色板,和它们背后的裁决

色板库有两个来源:社区长期沉淀的高人气板(收割时逐块过客观闸),以及使用者验收后的裁决入库——每一次"这个配色通过"的决定都会让库向使用者的真实口味靠近一步。目前库内 117 块,其中 30 块来自验收裁决。

匹配不是检索关键词,而是语域:医疗教学页与电商大促页会得到不同的候选序列,且候选都要先过同一套客观闸。偏好档案(深色惩罚、禁用色族、已验证板)随裁决持续更新,机械地作用于每一次匹配。

06
FIELD NOTES

两个使用场景

CASE 1系列视频封面的身份色锁定

一套医学科普视频系列,二十余期封面共用同一块五色板作为系列身份。色板锁定后,每期只更换构图与标题元素——观众不看节目名也能凭颜色认出系列。闸门在这条管线里的职责是防止"某一张忽然跑色":每期封面交付前过一次对比度与签名检查。

CASE 2医疗教学长页面的可读性兜底

长篇教学页面正文量大、层级深,最常见的问题不是"不好看",而是"某一段忽然读不清"。交付前的 HTML 审计逐点检查文字对底色的对比度,渐变与高饱和签名直接判不合格——对以可读性为生命的医学内容,这道闸是兜底而不是装饰。
